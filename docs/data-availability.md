# 数据可用范围

## 先看结论

| 周期 | 默认数据源 | 历史范围 | 需要注意 |
|---|---|---|---|
| `1` 分钟 | AKShare / 东方财富 | 通常最近 5 个交易日 | 不适合长期 1 分钟回填 |
| `5/15/30/60` 分钟 | AKShare / 东方财富，失败时新浪回退 | 由上游实际返回决定 | 回退源可能更短，新浪没有成交额 |

“请求成功”不等于“请求日期范围内每一天都有数据”。项目会把没有返回行的日期记为 `empty`，而不是伪造数据。

## 数据源顺序

默认 Provider 顺序是：

1. AKShare 的 `fund_etf_hist_min_em`；
2. 东方财富 curl 直连；
3. `5/15/30/60` 分钟周期的新浪历史分钟接口。

新浪接口返回的数据没有成交额，因此回退数据的 `amount` 保持为空。成交量 `vol` 和成交额 `amount` 不会互相替代。

当前 fallback 是“源级切换”：东方财富返回非空数据时，项目不会再把新浪数据拼接进来；只有请求失败或返回空结果时才进入下一层。这意味着不同数据源之间不会自动做缺口拼接。

## 日期和交易日

CLI 使用 `YYYYMMDD` 日期，日期范围按自然日计算。周末和节假日通常没有对应分区；是否有数据由上游返回决定。

对于 `period=1`，如果日期早于上游允许的窗口：

- Provider 可能返回空表；
- `fetch_symbol_range()` 会把对应日期记为 `empty`；
- 如果整批没有写入或跳过任何分区，CLI 会返回非零退出码。

## ETF universe 和历史时点

`--universe cn-etf` 默认从 `fund_etf_spot_em()` 获取当前 ETF 列表。使用 `--as-of YYYYMMDD` 或 `--fund-type` 时，会使用带查询日期的历史 ETF 快照。

这可以避免直接用“今天仍然存在的 ETF 列表”回填历史时点，降低幸存者偏差。但它不等于独立的官方生命周期表：当前项目还没有稳定、对称的 `list_date` / `delist_date` 元数据源。

## 输出 schema

每个交易日分区默认写入：

```text
<out>/<ts_code>/trade_date=YYYYMMDD/part.parquet
```

字段：

| 字段 | 类型/含义 |
|---|---|
| `ts_code` | 标准化代码，例如 `512880.SH` |
| `trade_time` | 分钟时间戳 |
| `open` / `high` / `low` / `close` | OHLC |
| `vol` | 成交量 |
| `amount` | 成交额；新浪回退时可能为空 |

## 数据质量建议

- 先用 `etf-min-check` 验证网络和上游 schema。
- 研究长期历史时，检查每个日期分区是否存在，不要只看命令是否成功退出。
- 对新浪回退数据单独处理 `amount` 空值。
- 记录下载日期、周期、命令参数和 checkpoint，保证结果可复现。
